# 使用细节

## 可调参数

发起测试前可自定义下面这些参数，它们直接对应 iperf3 / ping 原生命令：

| 界面项 | 对应参数 | 默认 | 范围 | 说明 |
|:--|:--|:--|:--|:--|
| 线程数 | `iperf3 -P` | 1 | 1–32 | 并行流数；多流才能吃满高带宽链路 |
| 单向时长 | `iperf3 -t` | 10 秒 | 1–300 | 上行、下行各跑一次 |
| iperf3 端口 | `iperf3 -p` | 5201 | 1–65535 | 目标机 `iperf3 -s` 的端口，防火墙需放行 |
| UDP 测试 | `iperf3 -u` | 关 | — | 勾选后按 UDP 发包，报告增加 UDP 丢包 / 抖动两列 |
| UDP 带宽/流 | `iperf3 -b` | 100M | `100M`/`1G`/`500K`（必须带单位） | **按流生效**：`-P 4 -b 100M` 的总目标是 400M |
| ping 次数 | `ping -c` | 200 | 1–2000 | 固定 `-i 1`，所以次数≈秒数 |

> UDP 测试要同时在目标机防火墙放行该端口的 **UDP**（TCP 与 UDP 是两套规则）；
> 面板会在开测前对目标机端口做一次预检，不通会提示并尝试自动重启目标机 server。

## 一轮测试做什么

1. **目标机**：检查/安装 `iperf3` 与 `ping`，按设定端口启动 `iperf3 -s`；
2. **每台后端机**：环境检查（并行）→ 按参数执行 iperf3 上行 → 下行（`-R`）→ ping；
3. 全部结束后关闭目标机的 iperf3 server，生成报告。

**iperf3 全局串行**（多台同时测速会互相抢带宽，结果作废），**ping 不占测速通道**，与其它机器的 iperf3 并行执行。

总时长 ≈ 1 分钟（环境准备）+ 台数 ×（2 × 单向时长 + 5 秒），ping 与后续机器的 iperf3 重叠进行。

## 测试协议：IPv4 / IPv6

默认 **IPv4**：iperf3 与 ping 都用目标机的 IPv4 地址，两端固定为 IPv4——避免个别机器没有 IPv6 时整轮测试失败。

需要测 IPv6 时勾选「**使用 IPv6 测试（需双端均支持 IPv6）**」（会二次确认）。勾选后改用目标机的 IPv6 地址，**所有选中的后端机器都必须具备 IPv6 连通性**，否则该台失败；面板会在选项旁提示未探测到 IPv6 的后端机器，目标机只有 IPv6 时会自动选中。

## 机器地址怎么来的

无需手填，面板自动采集：

- **心跳观测**：Agent 心跳的来源 IP 按协议族分别记录（双栈面板下 v4/v6 互不覆盖，地址不会在两族之间跳动）；
- **本机探测**：地址不全时，面板通过签名任务让 Agent 在本机执行一次地址探测（`ip route get` / `ip -6 addr`，只做本地查询，不访问外网、不产生流量），因此**面板只监听 IPv4 也能拿到机器的 IPv6**；Agent 无需升级即可支持；
- **展示规则**：机器列表「测试地址」列只显示真正会用于测试的那个地址——双栈机器只显示 IPv4（有没有 IPv6 在后端机器备注里以绿色「有 V6」/ 橙色「无 IPv6」标出），只有 IPv6 的机器才显示 IPv6；「探测地址」按钮可手动刷新（例如机器换 IP 后），探测失败会在地址旁标 ⚠️，鼠标悬停看原因。

> 探测只接受全局可路由地址（私网、链路本地、ULA 会被忽略）；开启隐私扩展的机器优先取稳定地址，只有临时（temporary）地址的机器会退而使用临时地址，不会因为找不到稳定地址而完全探测不到 IPv6。处于 NAT 后的机器会沿用面板观测到的出口 IP。

## 报告

Markdown 报告包含：本次测试参数（线程 / 时长 / 端口 / TCP-UDP / ping 次数）、线路质量评价，以及每台机器的丢包率、RTT（min/avg/max/mdev）、抖动、上行、下行、重传（UDP 测试改列为 UDP 丢包与 UDP 抖动），并附每台机器的原始 ping 与 iperf3 输出。

报告会对地址脱敏：IPv4 只保留 A.B 两段，IPv6 保留前两组。

## 端口与安全组

- **目标机**：放行所选测试端口（默认 5201；UDP 测试需同时放行该端口 UDP）与 ICMP（**建议只放行后端机 IP**，防止被扫描盗刷流量）；
- **面板机**：放行 `.env` 里的端口；启用 HTTPS 后建议追加 `PANEL_BIND=127.0.0.1`，只保留 80/443；
- 跨公网建议套 HTTPS 反代，配置见 [deploy.md](deploy.md)。
